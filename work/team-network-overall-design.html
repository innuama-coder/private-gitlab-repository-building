TEAM NETWORK / MULTI-EDGE DESIGN

多公网接入的公司内网总体设计

Mac Studio 是家庭核心节点，ECS1 至 ECS6 全部通过各自的 Tailscale 链路访问它；其中多个 ECS 还可以组成 GitLab 公网接入池，分摊单台 ECS4 的入口压力。

唯一家庭核心Mac Studio
六个访问节点ECS1 至 ECS6
目标流量进隧道只有访问 Mac Studio
物理上限仍受家庭上行约束
01

核心结论

正确模型是：Mac Studio 需要 Tailscale 解决家庭网络入站问题；ECS1 至 ECS6 都安装 Tailscale，作为访问 Mac Studio 的固定公网节点。它们自己的公网、Wiki、Agent 和开发测试流量仍走原来的固定 IP 网络。

关键边界：多台 ECS 可以消除单台 ECS4 的公网入口瓶颈并提供故障切换，但不能突破 Mac Studio 家庭网络上行带宽总上限。Tailscale 也不会把一条单独的 Git 连接拆到多台 ECS 上。

因此，本方案是“ECS 固定 IP + 目标流量走 Tailscale + Mac Studio 家庭服务”的混合架构，不是全网默认代理。

04

Tailscale 部署方案

部署范围

安装在 Mac Studio、五名成员设备和 ECS1 至 ECS6。六台 ECS 都可以访问 Mac Studio；其中选定节点额外承担公网 GitLab gateway。

建立公司 tailnet使用 whale-smart.com 身份，启用 SSO、MFA、登录通知和两名恢复管理员。
加入 Mac Studio固定主机名 mac-studio，保留本机控制台和家庭局域网恢复路径。
加入 ECS1 至 ECS6每台 ECS 使用自己的主机名、标签、auth key、系统账号和管理密钥；只有 gateway 节点运行公网代理。
成员设备登录五名成员分别 SSO 登录，设备丢失时单独撤销。

ECS 加入命令

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up \
  --hostname=ecs1-macstudio-access \
  --auth-key="$TS_AUTHKEY" \
  --advertise-tags=tag:macstudio-access \
  --accept-routes=false \
  --accept-dns=false
sudo tailscale status
sudo tailscale ip -4
sudo tailscale netcheck
  • 不使用 --advertise-routes 和 --advertise-exit-node。
  • 服务器使用 --accept-dns=false，避免复现 ECS5 的 DNS 冲突。
  • 每台 gateway 只允许访问 Mac Studio 的 GitLab 443、2222。
  • 成员设备可以直连 Mac Studio，不依赖任何单一 ECS。
05

多公网接入设计

统一代理配置443 反代 GitLab Web；2222 TCP 转发 Git SSH；不缓存、不落盘。
DNS 分流git.whale-smart.com 返回启用 gateway 的固定 IP，TTL 先用 60 至 120 秒。
目标链路每个 ECS 到 Mac Studio 的访问走 Tailscale；其他 ECS 流量保持固定 IP 网络。

接入节点选型

ECS1 至 ECS6 统一测试公网带宽、持续传输、时延、丢包、Tailscale direct/DERP、资源余量和故障影响。至少保留两个通过测试的 gateway，不能只按历史角色选 ECS4。

性能事实：多 gateway 分摊多用户、多连接的入口压力；单个 clone 连接仍只经过一个 gateway，并受该 gateway 与家庭上行的较小值限制。
06

GitLab 访问与迁移

  • 公网用户：访问 git.whale-smart.com，由 DNS 选择 gateway，再经 Tailscale 到 Mac Studio。
  • 成员用户：Tailscale 直连 Mac Studio，适合日常 Git、管理和大文件测试。
  • 两条路径访问同一个 GitLab 实例，external URL、回调和 SSH 地址保持一致。
先建新路径保留 ECS4 旧入口，先完成 Mac Studio、两个 gateway 和测试域名。
双路径验收五名成员测试直连；外部客户端测试每个 gateway 的 Web、HTTPS Git、SSH Git。
性能对比用大文件仓库记录直连、ECS4 和其他 gateway 的吞吐、错误和路径。
正式切换正式 DNS 指向 gateway 池，观察至少 24 小时，再决定是否下线 ECS4 旧入口。
07

Wiki 与固定 IP ECS 服务

Wiki 已确认位于 ECS3，公网 IP 为 8.221.138.205，域名为 wiki.whale-smart.com。本期不迁移 Wiki，但 ECS3 仍安装 Tailscale，以便按规则访问 Mac Studio。

  • Wiki 继续使用 ECS3 固定 IP、Caddy、HTTPS、云安全组和应用认证。
  • 其他 ECS 继续使用固定 IP 或正式域名访问；只有访问 Mac Studio 的目标流量走 Tailscale。
  • 如果未来要求 Wiki 仅 Team Network 可访问，需要把 Wiki 的访问边界单独切换到 Tailscale、身份代理或白名单方案。
不能混淆：Mac Studio 的 Tailscale 只保护 Mac Studio，不会自动把 ECS3 Wiki 变成私网服务。
08

安全、备份与可用性

最小权限gateway 只能到 Mac Studio GitLab 443/2222，不拥有其他内网端口权限。
独立身份每个 gateway 使用独立节点身份、系统账号、代理配置和 SSH 密钥。
故障范围gateway 故障可摘除；家庭断电或 Mac Studio 故障，多 gateway 也无法恢复核心服务。

60 分钟 RTO 适用于 Tailscale 重连、gateway 摘除、代理重启和 GitLab 容器故障。家庭网络或 Mac Studio 整机故障若也要纳入 60 分钟，必须增加云端温备或云端主服务。

GitLab 备份继续保存到独立目标；gateway 不保存仓库、制品、数据库或备份。监控 Tailscale 握手、gateway 健康、GitLab HTTPS、磁盘、容器和备份结果。
