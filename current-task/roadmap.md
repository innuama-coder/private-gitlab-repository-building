# 路线图

## 00. 执行规则

- 路线图只有一条主线，按 M1 到 M6 顺序推进。
- 后一个里程碑必须以前一个里程碑“交付并验收通过”为前置条件。
- 每个里程碑只解决一个内聚问题，并交付可以单独使用或验证的成果。
- 任何验收不通过时，停在当前里程碑修复，不跨步堆积问题。
- 六要素已经冻结；若实施中出现目标、边界或验收变化，先走显式解冻流程。

## M1. 节点与私网基线

### 目的

让主节点、入口节点和备份节点具备可管理的基础环境，并先打通 Mac Studio 与 ECS4 的 Tailscale 私网链路。

### 工作范围

- 确认 Mac Studio、ECS4、ECS5 的身份、地址和角色。
- 在 Mac Studio 准备 Linux 容器运行环境和持久化数据目录。
- 在 Mac Studio、ECS4、ECS5 配置 Tailscale 私网连接。
- 在 ECS4 配置最小防火墙规则和管理 SSH 来源限制。
- 在 Mac Studio 关闭自动睡眠，确认接电后自动恢复策略。

### 独立交付物

- 三个节点的角色与地址清单。
- Mac Studio 容器运行环境和数据目录。
- Tailscale 节点连接配置。
- ECS4 基础防火墙配置。

### 独立验收方法

- 从 ECS4 通过 Tailscale SSH 访问 Mac Studio。
- 从 Mac Studio 通过 Tailscale 访问 ECS5。
- 重启或重新连接后，三个节点仍能恢复到预期连接状态。
- 从公网扫描时，Mac Studio 没有直接暴露 GitLab 服务端口。

### 完成定义

私网链路稳定，节点角色明确，主节点具备承载服务的运行基础；否则不进入 M2。

## M2. GitLab 核心服务

### 目的

在 Mac Studio 上交付一个可通过 Tailscale 访问的 GitLab 核心服务，先验证代码托管和协作基础。

### 前置条件

- M1 已验收通过。

### 工作范围

- 使用官方 GitLab CE 容器镜像部署单节点 GitLab。
- 分离配置、日志、仓库、数据库和制品的持久化目录。
- 设置 GitLab 外部 URL 的正式域名占位配置。
- 创建管理员账号并启用强密码和双因素认证。
- 创建一个私有示例项目和一个测试账号。

### 独立交付物

- Mac Studio 上运行的 GitLab 核心服务。
- GitLab 持久化目录和部署配置。
- 管理员账号、测试项目和测试账号。

### 独立验收方法

- 通过 Tailscale 访问 GitLab 登录页并登录管理员账号。
- 创建私有项目。
- 测试账号只能看到被授权的项目。
- 通过 Tailscale 完成一次项目创建、代码提交和项目读取。
- 重启 GitLab 容器后，项目和账号仍然存在。

### 完成定义

GitLab 核心服务可登录、可保存项目、可执行基础权限控制，并且重启后数据不丢失；否则不进入 M3。

## M3. 公网访问入口

### 目的

让外部用户可以通过正式域名访问 GitLab，同时保持 Mac Studio 不直接暴露公网。

### 前置条件

- M2 已验收通过。
- 已取得正式域名和 ECS4 公网 IP。

### 工作范围

- 将域名 A 记录指向 ECS4。
- 在 ECS4 部署 Caddy 或 Nginx。
- 配置 HTTPS 证书自动申请和续期。
- 通过 Tailscale 将 Web 请求转发到 Mac Studio。
- 配置 Git HTTPS 访问。
- 将 Git SSH 连接从 ECS4 转发到 GitLab SSH 服务；如与管理 SSH 冲突，使用独立端口或明确的转发规则。

### 独立交付物

- 正式 GitLab 域名。
- ECS4 反向代理配置。
- HTTPS 证书和续期配置。
- Web、Git HTTPS、Git SSH 的访问配置。

### 独立验收方法

- 使用不在家庭网络中的客户端打开正式域名。
- 页面使用有效 HTTPS 证书并可以登录。
- 通过公网 HTTPS 完成 `clone`、`push`、`pull`。
- 通过公网 SSH 完成 `clone`、`push`、`pull`。
- 关闭或断开 Mac Studio 的公网直连条件，确认外部流量仍只经过 ECS4 和 Tailscale。

### 完成定义

外部用户可以用正式域名完成 Web、HTTPS Git 和 SSH Git 访问，Mac Studio 没有直接公网入口；否则不进入 M4。

## M4. CI/CD 工作流

### 目的

交付可以独立运行和诊断的 GitLab CI/CD 闭环。

### 前置条件

- M3 已验收通过。

### 工作范围

- 在 Mac Studio 配置 GitLab Runner。
- 使用 Docker executor 隔离构建任务。
- 以 ARM64 为默认构建架构。
- 创建示例 `.gitlab-ci.yml`，包含测试、构建和制品保存。
- 配置必要的 Runner 标签、缓存和权限。

### 独立交付物

- 已注册并可用的 GitLab Runner。
- 示例 CI/CD 配置。
- 一条可查看日志和制品的流水线。

### 独立验收方法

- 提交示例代码，流水线自动启动并成功完成。
- 查看每个阶段的日志。
- 下载并读取示例制品。
- 人为制造一次失败，确认失败原因能在日志中定位。
- 修复代码后重新运行，确认流水线成功。
- 如使用 amd64 镜像，单独记录跨架构验证结果；没有验证时不把它标为默认能力。

### 完成定义

Runner 能执行成功、失败、修复重跑和制品保存，CI/CD 结果可追溯；否则不进入 M5。

## M5. 备份与恢复能力

### 目的

交付一套真正可恢复的 GitLab 数据保护能力，而不是只生成备份文件。

### 前置条件

- M4 已验收通过。
- ECS5 已准备为独立备份目标。

### 工作范围

- 在 Mac Studio 配置每日 GitLab 备份。
- 将备份复制到 ECS5 独立目录。
- 设置备份保留数量、访问权限和校验记录。
- 记录 GitLab 配置、入口配置和恢复步骤。
- 恢复一个测试项目到测试位置。

### 独立交付物

- 定时备份任务。
- ECS5 备份目录和权限配置。
- 备份校验记录。
- 可执行的恢复步骤和一次恢复结果。

### 独立验收方法

- 手动执行一次备份并确认任务成功。
- 在 ECS5 找到对应备份，核对时间、大小和校验结果。
- 删除测试位置的副本后，从备份恢复项目。
- 读取恢复后的项目并完成一次 Git 操作。
- 确认备份不依赖公网入口节点的 GitLab 数据目录。

### 完成定义

备份能生成、复制、读取和恢复，恢复结果可被实际使用；否则不进入 M6。

## M6. 首期发布与全链路验收

### 目的

把前五个独立成果组合成可交付的首期服务，并用冻结六要素中的全部验收标准做一次完整复核。

### 前置条件

- M1 至 M5 全部验收通过。

### 工作范围

- 固化 GitLab、Runner、反向代理和 Tailscale 的版本与配置。
- 执行管理员、测试账号、SSH、HTTPS、CI/CD、备份和恢复的全链路测试。
- 重启 Mac Studio 和相关容器，检查服务自动恢复。
- 暂时断开 Tailscale，检查公网入口行为；恢复后再次验证。
- 整理配置、命令输出、流水线记录、备份记录和故障处理说明。

### 独立交付物

- 首期可用的 GitLab 服务。
- 全链路验收记录。
- 配置清单和版本清单。
- 日常维护、故障处理和恢复说明。
- 下一阶段观察指标和升级触发记录。

### 独立验收方法

- 按冻结六要素的“访问与身份”清单逐项验证。
- 按“Git 操作”清单验证 SSH、HTTPS、权限和私有项目。
- 按“CI/CD”清单验证成功、失败、重跑、日志和制品。
- 按“可靠性与恢复”清单验证备份、恢复、重启和 Tailscale 断连恢复。
- 每项验收都保留命令输出、流水线编号、截图或文件位置。

### 完成定义

冻结六要素中的验收标准全部有通过证据，维护者可以依据交付说明继续使用和恢复服务，首期任务正式完成。

## 07. 后续升级触发条件

只有出现以下事实，才启动下一轮方案设计：

- GitLab 内存或磁盘持续接近容量上限。
- 家庭网络中断已经影响工作频率。
- 流水线并发量超过单个 Runner 的处理能力。
- 公网入口需要故障切换。
- 恢复演练无法达到预期时间或完整性要求。
